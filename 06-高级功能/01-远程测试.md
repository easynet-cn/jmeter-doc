# 01 - 远程测试

远程测试允许一台 JMeter 客户端控制多台远程 JMeter 引擎。当单机无法模拟足够用户时使用。

## 核心概念

**关键理解**：JMeter **不分摊负载**，每个服务器执行**完整测试计划**。如果设置 1000 线程、6 台服务器，则总共注入 **6000 线程**。

---

## 配置步骤

### Step 0：配置节点（最关键）

所有机器（客户端和服务器）必须保持一致：

| 要求 | 说明 |
|------|------|
| **相同 JMeter 版本** | 所有节点必须运行完全相同版本 |
| **相同 Java 版本** | 强烈建议相同版本 |
| **SSL/RMI 配置** | 自 JMeter 4.0 起，RMI 默认使用 SSL |
| **数据文件** | CSV 数据文件**不会**自动发送，需手动复制到每台服务器 |

#### 生成 RMI 密钥库

```bash
# 在 bin 目录下执行
./create-rmi-keystore.sh    # Linux/macOS
create-rmi-keystore.bat     # Windows
```

将生成的 `rmi_keystore.jks` 复制到所有机器。

#### 禁用 SSL（不推荐）

```properties
# user.properties
server.rmi.ssl.disable=true
```

### Step 1：启动服务器

```bash
# Linux/macOS
jmeter-server

# Windows
jmeter-server.bat
```

每个节点只能运行一个 JMeter 服务器。

### Step 2：配置客户端

在客户端的 `user.properties` 中：

```properties
remote_hosts=192.168.1.100,192.168.1.101,192.168.1.102
```

### Step 3：启动测试

**GUI 模式（仅调试）**：
- Run 菜单中出现 "Remote Start" 和 "Remote Stop" 选项

**CLI 模式（推荐）**：
```bash
# 启动所有远程服务器
jmeter -n -t script.jmx -r

# 启动指定服务器
jmeter -n -t script.jmx -R server1,server2

# 测试后生成报告
jmeter -n -t script.jmx -r -l results.jtl -e -o /path/to/dashboard
```

## 结果发送模式

`mode` 属性控制结果如何从服务器发送回客户端：

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| **Standard** | 同步发送每个样本 | 低吞吐量调试 |
| **Batch** | 达到阈值后批量发送 | 中等吞吐量 |
| **StrippedBatch**（默认） | 去除成功样本的响应数据 + 批量发送 | **推荐，高吞吐量** |
| **Statistical** | 仅发送摘要样本 | 最高吞吐量 |
| **Asynch** | 异步队列发送 | 需要非阻塞 |
| **StrippedAsynch** | Stripped + Asynch | 高吞吐 + 非阻塞 |

### 批量模式配置

```properties
mode=StrippedBatch
num_sample_threshold=100      # 累积 100 个样本后发送
time_threshold=60000          # 或每 60 秒发送一次
```

## 高级配置

### 自定义 RMI 端口

```bash
# 在远程服务器上
SERVER_PORT=4444 jmeter-server
```

### 防火墙配置

RMI 使用动态高端口，需要配置：

```properties
# 客户端本地端口
client.rmi.localport=50000
```

JMeter 将从此基础端口开始打开最多 3 个端口。

### 容错配置

```properties
client.tries=3                  # 重试 3 次
client.retries_delay=5000       # 间隔 5 秒
client.continue_on_fail=true    # 部分失败后继续
```

## 安全策略

启用 Java Security Manager 保护远程节点：

```properties
# 在 jmeter-server 启动时
-Djava.security.manager -Djava.security.policy=java.policy
```

示例 `java.policy`：
```
grant {
    permission java.net.SocketPermission "*:1024-65535", "connect,resolve";
};
```

---

## 故障排除

| 问题 | 可能原因 | 解决方案 |
|------|----------|----------|
| 服务器无法连接 | 防火墙阻止 | 开放 RMI 端口和动态端口 |
| 版本不匹配 | 不同 JMeter 版本 | 统一所有节点版本 |
| CSV 数据不同 | 文件未同步 | 手动复制数据文件 |
| SSL 握手失败 | 证书问题 | 重新生成并分发密钥库 |
| 结果丢失 | 网络延迟 | 调整批处理参数 |
