# 05 - 最佳实践

## 16.1 始终使用最新版本

JMeter 性能持续改进，强烈建议使用最新版本。避免使用比最新版本早 3 个版本以上的旧版本。

---

## 16.2 使用正确的线程数

### 影响因素

- 硬件能力
- 测试计划设计复杂度
- 目标服务器响应速度（更快的服务器让 JMeter 工作更努力）

### 建议

- 如需大规模负载测试，使用**分布式模式**
- 使用 **JavaTest Sampler** 测试 JMeter 在给定平台的性能上限
- 可延迟线程创建，直到线程开始采样，允许非常大的总线程数

## 16.3-16.4 Manager 放置位置

- **Cookie Manager**：放在 Thread Group 级别，影响所有 Web 请求
- **Authorization Manager**：放在需要认证的作用域内

## 16.5 使用 HTTP(S) Test Script Recorder

### 过滤是关键

- 排除图片等静态资源请求：`.*\\.(bmp|css|js|gif|ico|jpe?g|png|swf|woff)`
- 仅包含业务请求：`.*\\.(jsp|asp|php|html|do)`

### 录制流程

1. 添加 Thread Group + Recording Controller
2. 添加 HTTP(S) Test Script Recorder
3. 配置浏览器代理（默认 `localhost:8888`）
4. 安装 CA 证书以录制 HTTPS
5. 录制完成后清理和参数化

## 16.7 减少资源需求

| 建议 | 说明 |
|------|------|
| **使用 CLI 模式** | `jmeter -n -t test.jmx -l test.jtl` |
| **减少监听器** | 负载测试期间禁用 View Results Tree |
| **使用 CSV 输出** | 比 XML 更高效 |
| **仅保存必要数据** | 关闭响应数据保存 |
| **减少断言** | 仅添加必要的断言 |
| **使用循环复用采样器** | 用变量改变采样参数 |

## 16.12 JSR223 元素

### 推荐脚本语言

对于密集负载测试，推荐使用实现了 `Compilable` 接口的 ScriptingEngine：

- **Groovy**（推荐）：实现了 Compilable，性能最佳
- BeanShell 和 JavaScript 在 JMeter 3.1 时未实现 Compilable

### 最佳实践

- 勾选 **"Cache compiled script if available"**
- 使用 `vars.get("varName")` 而非 `${varName}`
- 避免在脚本中执行 I/O 操作

```groovy
// ✅ 推荐
def count = vars.get("counter") as int
vars.put("result", (count + 1).toString())

// ❌ 避免
// def count = ${counter}
```

## 16.14 管理属性

**不要修改 `jmeter.properties`！** 在 `user.properties` 中覆盖属性。

```properties

```

## 性能优化总结

### GUI vs CLI

| 模式 | 用途 | 资源消耗 |
|------|------|----------|
| **GUI** | 创建和调试脚本 | 高 |
| **CLI** | 实际负载测试 | 低 |

### 监听器影响

| 监听器 | 负载测试建议 |
|--------|-------------|
| View Results Tree | ❌ 禁用 |
| View Results in Table | ❌ 禁用 |
| Graph Results | ❌ 禁用 |
| Aggregate Report | ⚠️ 仅保存到文件 |
| Simple Data Writer | ✅ 推荐 |
| Backend Listener | ✅ 推荐 |

### 脚本语言性能

| 语言 | 性能 | 推荐 |
|------|------|------|
| Groovy | 高 | ✅ |
| JEXL3 | 高 | ✅（简单表达式） |
| BeanShell | 低 | ❌ |
| JavaScript | 低 | ❌ |
