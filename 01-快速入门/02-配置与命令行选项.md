# 02 - 配置与命令行选项

## 1.4 运行 JMeter

### 启动文件

| 平台 | 脚本 | 说明 |
|------|------|------|
| Windows | `jmeter.bat` | 标准启动（带控制台窗口） |
| Windows | `jmeterw.cmd` | 无控制台窗口启动 |
| Linux/Unix/macOS | `jmeter` 或 `jmeter.sh` | 标准启动 |

### 1.4.1 JMeter 类路径

JMeter 自动从以下位置查找类：

| 目录 | 用途 |
|------|------|
| `lib/` | 工具 jar 包 |
| `lib/ext/` | JMeter 组件和插件 |

如需添加额外的 jar 包（JDBC 驱动、JMS 客户端等），将其放入 `lib/` 目录或通过属性配置。

### 1.4.2 从模板创建测试计划

JMeter 提供预定义的测试计划模板，可通过菜单 **File → Templates…** 访问。模板包括：

- 录制模板
- 构建 Web 测试计划
- 构建高级 Web 测试计划
- JDBC 负载测试
- 等等

### 1.4.3 在代理后使用 JMeter

通过命令行参数设置代理：

```bash
jmeter -H <代理主机> -P <代理端口>
```

选项说明：

| 选项 | 说明 |
|------|------|
| `-H, --proxyHost` | 代理服务器主机名或 IP |
| `-P, --proxyPort` | 代理服务器端口 |
| `-u, --username` | 代理认证用户名 |
| `-a, --password` | 代理认证密码 |
| `-N, --nonProxyHosts` | 不使用代理的主机列表（正则表达式） |

### 1.4.4 命令行模式（CLI）

**这是运行实际负载测试的推荐方式。** GUI 模式仅应用于调试。

```bash
jmeter -n -t test.jmx -l results.jtl
```

基本 CLI 选项：

| 选项 | 说明 |
|------|------|
| `-n` | CLI（非 GUI）模式 |
| `-t, --testfile` | 指定 JMX 测试文件 |
| `-l, --logfile` | 记录样本结果到文件 |
| `-j, --jmeterlogfile` | JMeter 运行日志文件 |

### 1.4.5 服务器模式

在远程机器上启动 JMeter 服务器：

```bash
# Linux/Unix/macOS
jmeter-server

# Windows
jmeter-server.bat
```

### 1.4.6 通过命令行覆盖属性

```bash
# 设置 JMeter 属性
jmeter -J属性名=值

# 设置系统属性
jmeter -D属性名=值

# 设置全局属性（发送到远程服务器）
jmeter -G属性名=值
```

### 1.4.7 日志和错误消息

JMeter 将警告和错误报告到 `jmeter.log` 文件。可通过 `-L` 选项覆盖日志级别：

```bash
# 将特定包的日志级别设置为 DEBUG
jmeter -Ljmeter.engine=DEBUG

# 设置根日志级别
jmeter -LDEBUG
```

### 1.4.8 命令行选项完整列表

| 选项 | 说明 |
|------|------|
| `-n` | 在 CLI（非 GUI）模式下运行 |
| `-t [file]` | 指定 JMX 测试文件 |
| `-l [file]` | 将样本结果记录到文件 |
| `-j [file]` | JMeter 运行日志文件 |
| `-r` | 启动远程服务器（由 `remote_hosts` 定义） |
| `-R [hosts]` | 启动指定远程服务器 |
| `-e` | 负载测试后生成报告仪表板 |
| `-o [folder]` | 报告仪表板的输出文件夹 |
| `-g [file]` | 仅从结果文件生成报告仪表板 |
| `-H [host]` | 代理主机 |
| `-P [port]` | 代理端口 |
| `-J[prop]=[val]` | 定义其他 JMeter 属性 |
| `-G[prop]=[val]` | 定义全局属性（发送到服务器） |
| `-D[prop]=[val]` | 定义系统属性 |
| `-L[category]=[level]` | 覆盖日志级别 |
| `-s` | 启动 JMeter 服务器 |
| `-X` | 测试结束后远程服务器自动退出 |
| `-p, --propfile` | 使用自定义属性文件 |
| `-q, --addprop` | 加载额外的属性文件 |
| `-v, --version` | 显示版本信息 |
| `-h, --help` | 显示帮助信息 |

### 1.4.9 CLI 模式关闭

JMeter CLI 模式在指定端口（默认 **4445**，可通过 `jmeterengine.nongui.port` 配置）监听命令：

| 命令 | 脚本 | 说明 |
|------|------|------|
| **Shutdown** | `shutdown.sh` / `shutdown.cmd` | 优雅关闭 |
| **StopTestNow** | `stoptest.sh` / `stoptest.cmd` | 立即停止 |

## 1.5 配置 JMeter

### 配置文件处理顺序

1. `-p propfile` 指定的属性文件
2. `jmeter.properties` 加载
3. `-j logfile` 设置日志文件
4. 初始化日志
5. `user.properties` 加载
6. `system.properties` 加载
7. 处理所有其他命令行选项

### 关键配置文件

| 文件 | 用途 |
|------|------|
| `jmeter.properties` | 主配置文件（只有 `language` 必须在此设置） |
| `user.properties` | 用户自定义覆盖（推荐在此自定义） |
| `system.properties` | 系统级属性（SSL 等） |
| `hc.parameters` | Apache HttpClient 参数覆盖 |
| `upgrade.properties` | 向后兼容名称映射 |
| `templates.xml` | 模板定义 |

### 常用配置属性

| 属性 | 说明 |
|------|------|
| `ssl.provider` | 自定义 SSL 实现类 |
| `xml.parser` | XML 解析器实现 |
| `remote_hosts` | 远程 JMeter 主机列表（逗号分隔） |
| `not_in_menu` | 从菜单中隐藏的组件 |
| `search_paths` | JMeter 插件类的额外路径 |
| `user.classpath` | 工具和依赖类的路径 |
| `plugin_dependency_paths` | 插件依赖路径 |

### 最佳实践

- **GUI 模式仅用于创建/调试测试脚本**
- **CLI 模式用于实际负载测试**——绝不要在 GUI 模式下运行负载测试
- 使用 HTML 报告分析负载测试结果
- 不要修改 `jmeter.properties`，在 `user.properties` 中进行自定义
