# 02 - 提示和技巧

## 测试计划设计

### 模块化设计

- 使用 **Test Fragment** + **Module Controller** 复用公共逻辑
- 使用 **Include Controller** 引用外部测试文件
- 将登录等公共操作抽取为独立模块

### 参数化

- 使用 **CSV Data Set Config** 实现数据驱动测试
- 使用 `__P()` 函数通过命令行参数化
- 使用 **User Defined Variables** 集中管理常量

### 变量命名

- 运行期间不变的变量：全大写或带前缀（如 `C_HOST`、`K_TIMEOUT`）
- 动态变量：使用有意义的名称（如 `extractedToken`、`userId`）

## 调试技巧

### 使用 Debug Sampler

在测试计划中添加 **Debug Sampler** + **View Results Tree**，查看当前所有变量和属性的值。

### 使用 Assertion Results

添加 **Assertion Results** 监听器，专门查看断言通过/失败情况。

### 使用 log 函数

```bash
${__log(Current value: ${varName})}
${__logn(Debug message)}  # 仅记录不返回值
```

### 逐步构建

1. 先添加 1 个线程 + 1 次循环验证
2. 逐步添加更多逻辑
3. 确认无误后再扩大规模

## 性能优化

### 分布式测试

当单机无法模拟足够用户时：
```bash
jmeter -n -t test.jmx -R server1,server2 -l results.jtl
```

### 结果保存优化

```properties
# 使用 CSV 格式
jmeter.save.saveservice.output_format=csv
# 关闭响应数据保存
jmeter.save.saveservice.response_data=false
# 仅保存失败的响应数据
jmeter.save.saveservice.response_data.on_error=true
```

## 常见问题

### Q: 测试运行时 GUI 卡顿？
**A**: 使用 CLI 模式运行实际测试。GUI 仅用于创建和调试。

### Q: 如何模拟不同用户的登录？
**A**: 使用 CSV Data Set Config 读取用户名/密码文件。

### Q: 如何提取动态 Token？
**A**: 使用 Regular Expression Extractor 或 JSON Extractor 从响应中提取。

### Q: 远程测试中 CSV 文件不工作？
**A**: CSV 数据文件不会自动同步，需手动复制到所有远程服务器。

### Q: 断言失败但响应正常？
**A**: 检查断言的作用域是否正确，确认 Pattern Matching Rules 设置。

### Q: 内存不足 (OutOfMemoryError)？
**A**: 增大 HEAP 内存：
```bash
# setenv.sh / setenv.bat
HEAP="-Xms2g -Xmx4g -XX:MaxMetaspaceSize=512m"
```

### Q: 如何模拟慢速网络？
**A**: 使用 CPS (characters per second) 模拟：
```properties
httpclient.socket.http.cps=50000   # 50 KB/s
```
