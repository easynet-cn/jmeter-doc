# 01 - 测试计划元素总览

## 3.0 测试计划 (Test Plan)

测试计划是 JMeter 测试的根元素。每个测试计划都包含一个 **"Functional Testing"（功能测试）** 复选框：

- **选中后**：JMeter 会记录每个样本从服务器返回的数据
- 如果监听器中指定了文件，数据将写入文件
- 适用于小规模运行以验证配置是否正确
- **压力测试时应关闭此选项**（默认关闭）

---

## 3.1 线程组 (Thread Group)

线程组是所有测试计划的起点。**所有控制器和采样器必须位于线程组之下。**

### 核心控制项

| 控制项 | 说明 |
|--------|------|
| **线程数** | 设置并发线程数量（模拟用户数） |
| **Ramp-Up 周期** | JMeter 达到全部线程数所需的时间（秒） |
| **循环次数** | 测试执行的次数 |

### Ramp-Up 计算示例

| 线程数 | Ramp-Up 周期 | 线程启动间隔 |
|--------|-------------|-------------|
| 10 | 100 秒 | 每 10 秒启动一个线程 |
| 30 | 120 秒 | 每 4 秒启动一个线程 |
| 5 | 5 秒 | 每 1 秒启动一个线程 |

> **建议**：Ramp-Up 初始值设为线程数，再根据需要进行调整。

### 线程生命周期设置

- **Duration（持续时间，秒）**：设定测试运行的总时长
- **Startup Delay（启动延迟，秒）**：JMeter 启动后的等待时间

---

## 3.2 控制器 (Controllers)

JMeter 有两种控制器类型：

### 3.2.1 采样器 (Samplers)

采样器告诉 JMeter 向服务器发送请求并等待响应。按在树中出现的顺序处理。

**内置采样器包括**：

| 采样器 | 用途 |
|--------|------|
| FTP Request | FTP 文件上传/下载 |
| HTTP Request | HTTP/HTTPS 请求（也支持 SOAP/REST） |
| JDBC Request | 数据库 SQL 查询 |
| Java Object Request | 自定义 Java 类请求 |
| JMS Request | JMS 消息队列请求 |
| JUnit Test Request | 运行 JUnit 测试类 |
| LDAP Request | LDAP 目录查询 |
| Mail Request | 读取邮件 |
| OS Process Request | 执行操作系统命令 |
| TCP Request | TCP 连接请求 |

> 💡 **提示**：如果向同一服务器发送多个相同类型的请求，考虑使用 **Defaults 配置元素**来简化配置。

### 3.2.2 逻辑控制器 (Logic Controllers)

逻辑控制器可以：
- 改变子元素请求的**执行顺序**
- **修改**请求本身
- 使 JMeter **重复**请求

**示例测试树结构**：

```
Test Plan
  └─ Thread Group
       ├─ Once Only Controller
       │    └─ Login Request
       ├─ Load Search Page (HTTP Sampler)
       ├─ Interleave Controller
       │    ├─ Search "A"
       │    ├─ Search "B"
       │    └─ HTTP Default Request (Config)
       ├─ HTTP Default Request (Config)
       └─ Cookie Manager (Config)
```

**关键点**：
- **Once Only Controller**：登录请求仅第一次执行，后续迭代跳过
- **Interleave Controller**：每次传递一个子请求，保持顺序
- **HTTP Request Defaults**：抽象公共信息，填充子采样器的空白字段
- **Cookie Manager**：应添加到所有 Web 测试中

### 3.2.3 测试片段 (Test Fragments)

- 与线程组同级存在
- **不自动执行**，需通过 **Module Controller** 或 **Include Controller** 引用
- 纯粹用于测试计划内的代码复用

---

## 3.3 监听器 (Listeners)

监听器提供 JMeter 在运行期间收集的测试信息访问。

### 常见监听器

| 监听器 | 功能 |
|--------|------|
| **Graph Results** | 以图形方式绘制响应时间 |
| **View Results Tree** | 显示请求和响应的详细信息，支持 HTML/XML 展示 |
| **Aggregate Report** | 聚合统计信息 |
| **Summary Report** | 摘要统计信息 |

### 重要特性

- 所有监听器保存**相同的数据**，区别仅在于屏幕展示方式
- 每个监听器都有文件存储字段和配置按钮
- 可选择保存字段及 CSV/XML 格式
- 可在测试树的任意位置添加，仅收集**同级或下级**元素的数据

---

## 3.4 定时器 (Timers)

- 默认情况下，JMeter 线程**连续执行**采样器，无暂停
- **建议添加延迟**，否则可能因短时间内发送过多请求而压垮服务器
- 定时器使 JMeter 在每个采样器执行前暂停指定时间
- 多个定时器的时间会**累加**
- 可将定时器作为采样器或控制器的子元素，限制其适用范围

---

## 3.5 断言 (Assertions)

断言用于验证服务器返回的响应是否符合预期。

### 使用示例

- 断言 HTTP 响应包含特定文本（如 `</HTML>`）
- 可使用 Perl 风格的正则表达式
- 可指定响应包含文本，或完全匹配整个响应

### 关键点

- 断言适用于**其作用域内的所有采样器**
- 要限制断言仅适用于单个采样器，将其添加为该采样器的**子元素**
- 添加 **Assertion Listener** 查看断言结果
- 失败的断言会在 Tree View 和 Table Listeners 中显示，并计入错误百分比

---

## 3.6 配置元素 (Configuration Elements)

配置元素与采样器密切配合，可添加或修改请求（但不发送请求）。

### 作用域规则示例

```
Thread Group
  ├─ Simple Logic Controller
  │    ├─ Cookie Manager ← 仅对 Web Page 1 和 2 有效
  │    ├─ Web Page 1
  │    └─ Web Page 2
  └─ Web Page 3 ← 无法访问 Cookie Manager
```

### 优先级规则

- 树分支内的配置元素优先于"父"分支中的同名元素

### 特殊说明

- **User Defined Variables** 配置元素不同：无论放在何处，都在测试开始时处理，建议仅放在线程组开头

---

## 3.7 前置处理器 (Pre-Processor Elements)

- 在采样器请求**之前**执行操作
- 附加到采样器元素时，在该采样器运行**之前**执行
- 常用于：修改采样请求设置、更新未从响应文本提取的变量

---

## 3.8 后置处理器 (Post-Processor Elements)

- 在采样器请求**之后**执行操作
- 附加到采样器元素时，在该采样器运行**之后**执行
- 常用于：处理响应数据，提取值
