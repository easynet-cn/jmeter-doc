# 02 - 执行顺序与作用域规则

## 3.9 执行顺序 (Execution Order)

JMeter 中每个采样器执行时的处理顺序如下：

```
0. 配置元素 (Configuration Elements)
1. 前置处理器 (Pre-Processors)
2. 定时器 (Timers)
3. 采样器 (Sampler)
4. 后置处理器 (Post-Processors) — 除非 SampleResult 为 null
5. 断言 (Assertions) — 除非 SampleResult 为 null
6. 监听器 (Listeners) — 除非 SampleResult 为 null
```

### 执行顺序示例

假设测试计划结构如下：

```
Controller
  ├─ Post-Processor 1
  ├─ Sampler 1
  ├─ Sampler 2
  ├─ Timer 1
  ├─ Assertion 1
  ├─ Pre-Processor 1
  ├─ Timer 2
  └─ Post-Processor 2
```

当执行 Sampler 1 和 Sampler 2 时，实际顺序为：

```
Pre-Processor 1 → Timer 1 → Timer 2 → Sampler 1 → Post-Processor 1 → Post-Processor 2 → Assertion 1
Pre-Processor 1 → Timer 1 → Timer 2 → Sampler 2 → Post-Processor 1 → Post-Processor 2 → Assertion 1
```

> ⚠️ 定时器、断言、前后置处理器**仅在存在适用采样器时处理**。逻辑控制器和采样器按树中**出现顺序**处理。

## 3.10 作用域规则 (Scoping Rules)

### 元素分类

| 类型 | 元素 |
|------|------|
| **严格层级性** | 监听器、配置元素、后置处理器、前置处理器、断言、定时器 |
| **主要有序性** | 控制器、采样器 |

### 规则说明

- 层级元素适用于其**父级及所有后代**
- 断言作为请求的子元素 → 仅适用于该请求
- 断言作为控制器的子元素 → 适用于该控制器下的所有请求

### 复杂作用域示例

```
Test Plan
  └─ Thread Group
       ├─ Timer #2 (影响所有请求)
       ├─ Request One
       ├─ Controller
       │    ├─ Timer #1 (影响 Two, Three, Four)
       │    ├─ Request Two
       │    ├─ Request Three
       │    │    └─ Assertion #1 (仅影响 Request Three)
       │    └─ Request Four
```

**分析**：

| 请求 | 受影响的定时器 | 受影响的断言 |
|------|--------------|------------|
| Request One | Timer #2 | — |
| Request Two | Timer #1, Timer #2 | — |
| Request Three | Timer #1, Timer #2 | Assertion #1 |
| Request Four | Timer #1, Timer #2 | — |

### 特殊规则

- **Header Manager、Cookie Manager、Authorization Manager** 与 Configuration Default 元素处理方式不同
- Default 元素设置会**合并**到采样器可访问的值集中
- Manager 设置**不合并**：若作用域内有多个 Manager，仅使用一个，但目前无法指定使用哪一个

## 3.12 使用变量参数化测试

### 固定变量用法

```
HOST    = www.example.com
THREADS = 10
LOOPS   = 20
```

引用方式：`${HOST}`、`${THREADS}`、`${LOOPS}`

### 属性驱动变量用法（推荐）

```
HOST    = ${__P(host,www.example.com)}
THREADS = ${__P(threads,10)}
LOOPS   = ${__P(loops,20)}
```

### 命令行修改值

```bash
jmeter … -Jhost=www3.example.org -Jloops=13
```

### 命名建议

| 变量类型 | 命名约定 | 示例 |
|----------|----------|------|
| 运行期间不变的变量 | 使用前缀（如 `C_`、`K_`）或全大写 | `C_HOST`, `K_TIMEOUT` |
| 线程本地变量（计数器、正则提取值） | 使用不同的命名约定 | `user_loop_count` |

> ⚠️ **注意**：多个 UDV 元素定义同一变量时，最后一个生效；线程启动后，初始变量集复制到每个线程。
