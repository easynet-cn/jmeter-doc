# 18-图形化监听器与报告解读 📊

> **难度：★★★☆☆** | Graph Results + Aggregate Graph + Response Time Graph + Dashboard Report + Backend Listener

---

## 1. 场景概述

### 图形化监听器的价值

- **实时可视化**：在压测执行过程中直观看到性能趋势
- **问题定位**：通过图形快速发现性能拐点和异常波动
- **报告呈现**：为团队和管理层提供直观的性能报告
- **对比分析**：多轮压测结果的图形化对比

### JMeter 图形化工具全景

| 工具 | 实时 | 用途 | 性能开销 |
|------|:---:|------|:---:|
| **Graph Results** | ✅ | 基础实时图形 | 中 |
| **Aggregate Graph** | ✅ | 聚合数据柱状图 | 低 |
| **Response Time Graph** | ✅ | 响应时间趋势 | 中 |
| **View Results Tree** | ✅ | 请求/响应详情 | 高 |
| **Dashboard Report** | ❌ | 离线 HTML 报告 | 无（后处理） |
| **Backend Listener** | ✅ | 实时推送到外部系统 | 低 |
| **Generate Summary Results** | ❌ | 命令行摘要输出 | 低 |
| **Comparison Assertion Visualizer** | ❌ | 响应对比 | 低 |

## 2. Graph Results（实时图形）

### 2.1 配置

```
右键 Thread Group → Add → Listener → Graph Results
```

无需配置，启动测试后自动绘制。

### 2.2 图形解读

Graph Results 包含三个指标曲线：

| 曲线颜色 | 指标 | 含义 |
|----------|------|------|
| **黑色** | Data（数据） | 当前样本的响应时间中位数 |
| **蓝色** | Average（平均） | 平均响应时间 |
| **红色** | Median（中位数） | 响应时间中位数 |
| **绿色** | Deviation（偏差） | 标准差 |
| **紫色** | Throughput（吞吐） | 每分钟请求数 |

### 2.3 图形指标

```
底部数据面板：
├── No of Samples: 10000      # 总样本数
├── Latest Sample: 235ms      # 最新样本响应时间
├── Average: 180ms            # 平均响应时间
├── Deviation: 45ms           # 标准差
└── Throughput: 500/min       # 吞吐量
```

### 2.4 使用建议

- **调试阶段**：快速查看响应时间波动
- **不要用于高并发压测**：Graph Results 消耗大量内存和 CPU
- **GUI 压测专用**：命令行模式下不生成图形

## 3. Aggregate Graph（聚合图形）

### 3.1 配置

```
右键 Thread Group → Add → Listener → Aggregate Graph
```

### 3.2 图形解读

柱状图展示每个 Label 的聚合统计：

| 列 | 说明 |
|----|------|
| **Label** | 采样器名称 |
| **Samples** | 样本数 |
| **Average** | 平均响应时间 |
| **Median** | 中位数 |
| **90% Line** | 90% 请求的响应时间 |
| **95% Line** | 95% 请求的响应时间 |
| **99% Line** | 99% 请求的响应时间 |
| **Min** | 最小值 |
| **Max** | 最大值 |
| **Error %** | 错误率 |
| **Throughput** | 吞吐量 |
| **Received KB/sec** | 接收速率 |
| **Sent KB/sec** | 发送速率 |

### 3.3 使用建议

- **多接口对比**：同时展示不同接口的性能差异
- **性能开销低**：适合长时间压测监控
- **关注 Error %**：错误率升高是最危险的信号

## 4. Response Time Graph（响应时间趋势）

### 4.1 配置

```
右键 Thread Group → Add → Listener → Response Time Graph
```

### 4.2 图形解读

以时间轴展示响应时间的变化趋势：

```
Y 轴: 响应时间 (ms)
X 轴: 时间 (运行时长)

关键观察：
├── 趋势是否平稳 → 系统稳定
├── 是否持续上升 → 可能内存泄漏或连接堆积
├── 是否有尖刺   → 可能 GC 停顿或外部依赖波动
└── 是否突然下降 → 可能服务重启或切换
```

### 4.3 Interval 配置

| Interval 值 | 粒度 | 适用场景 |
|-------------|------|----------|
| `500` | 0.5 秒 | 精细观察 |
| `1000` | 1 秒（默认） | 常规观察 |
| `5000` | 5 秒 | 长时间压测 |
| `30000` | 30 秒 | 长周期稳定性测试 |

## 5. Dashboard Report（HTML 报告）

### 5.1 生成命令

```bash
# 从 JTL 文件生成 Dashboard
jmeter -g results.jtl -o ./report/

# 压测同时生成
jmeter -n -t test.jmx -l results.jtl -e -o ./report/

# 自定义 Dashboard 配置
jmeter -g results.jtl -o ./report/ \
  -Jjmeter.reportgenerator.overall_granularity=60000 \
  -Jjmeter.reportgenerator.report_title="My Performance Report"
```

### 5.2 Dashboard 报告结构

```
report/
├── index.html                          # 主报告页
├── content/
│   ├── pages/
│   │   ├── OverTime.html              # 趋势页
│   │   ├── Throughput.html            # 吞吐量
│   │   ├── ResponseTimes.html         # 响应时间
│   │   ├── Errors.html                # 错误分析
│   │   └── CustomGraphs.html          # 自定义图形
│   └── js/
├── sbadmin2-1.0.7/                    # UI 框架
└── statistics.json                    # 统计数据
```

### 5.3 Dashboard 核心图表解读

#### APDEX（Application Performance Index）

```
APDEX = (满意数 + 容忍数/2) / 总样本数

评分标准：
├── 0.94 - 1.00  → 🟢 Excellent（优秀）
├── 0.85 - 0.93  → 🟡 Good（良好）
├── 0.70 - 0.84  → 🟠 Fair（一般）
├── 0.50 - 0.69  → 🔴 Poor（差）
└── 0.00 - 0.49  → ⚫ Unacceptable（不可接受）
```

**自定义 APDEX 阈值**：

```properties
# user.properties
jmeter.reportgenerator.apdex_satisfied_threshold=500
jmeter.reportgenerator.apdex_tolerated_threshold=1500
```

#### Requests Summary

```
请求摘要卡片：
├── OK: 9998  (99.98%)
├── KO: 2     (0.02%)
├── Avg: 180ms
├── Min: 12ms
├── Max: 3456ms
├── Error%: 0.02%
└── Throughput: 500/sec
```

#### Response Times Over Time

时间轴上的响应时间趋势，含 90/95/99 分位线。

#### Response Time Percentiles

百分位分布柱状图，直观显示长尾分布。

#### Top 5 Errors by Sampler

错误排行，快速定位问题接口。

## 6. Backend Listener（实时数据推送）

### 6.1 推送到 InfluxDB + Grafana

```
Backend Listener
├── Backend Listener implementation:
│   org.apache.jmeter.visualizers.backend.influxdb.InfluxdbBackendListenerClient
├── influxdbMetricsSender:
│   org.apache.jmeter.visualizers.backend.influxdb.HttpMetricsSender
├── influxdbUrl: http://localhost:8086/write?db=jmeter
├── application: myApp
├── measurement: jmeter
├── summaryOnly: false
├── samplersRegex: .*
├── percentiles: 90;95;99
├── testTitle: Production Load Test
└── eventTags:
```

### 6.2 Grafana Dashboard 配置

使用 [JMeter Dashboard by Novatec](https://grafana.com/grafana/dashboards/1152-jmeter-load-test/) 或自定义面板：

```
典型 Grafana 面板布局：
┌─────────────────────────────────────────────┐
│  总览卡片                                    │
│  [总请求] [错误率] [平均RT] [TPS] [Active]  │
├─────────────────────┬───────────────────────┤
│  Response Time (ms) │  Throughput (req/s)   │
│  (折线图)           │  (折线图)             │
├─────────────────────┴───────────────────────┤
│  Response Time Percentile (堆叠面积图)       │
│  [90%] [95%] [99%]                         │
├─────────────────────────────────────────────┤
│  Error Rate (%) (折线图)                     │
├─────────────────────┬───────────────────────┤
│  Active Threads     │  Network I/O         │
└─────────────────────┴───────────────────────┘
```

### 6.3 InfluxDB 数据结构

```
measurement: jmeter
tags:
  ├── application=myApp
  ├── transaction=HTTP Request
  └── statut=ok

fields:
  ├── count=1000
  ├── avg=180.5
  ├── min=12

  ├── pct95.0=350.1
  ├── pct99.0=1200.5
  ├── hit=true
  └── errorCount=2
```

## 7. 监听器选择指南

| 场景 | 推荐监听器 | 原因 |
|------|-----------|------|
| **脚本调试** | View Results Tree | 查看请求/响应详情 |
| **GUI 实时监控** | Aggregate Report + Response Time Graph | 低开销 + 可视化趋势 |
| **命令行压测** | Generate Summary Results | 控制台摘要输出 |
| **正式报告** | Dashboard Report | 专业 HTML 报告 |
| **持续监控** | Backend Listener → InfluxDB → Grafana | 实时 + 历史对比 |
| **结果导出** | Simple Data Writer | 原始数据导出 |
| **断言可视化** | Assertion Results | 调试断言规则 |

## 8. 性能影响

| 监听器 | CPU 开销 | 内存开销 | 建议 |
|--------|:---:|:---:|------|
| **View Results Tree** | 中 | 高 | 仅调试时使用 |
| **Graph Results** | 高 | 中 | 仅短时间使用 |
| **Aggregate Report** | 低 | 低 | ✅ 适合压测 |
| **Aggregate Graph** | 低 | 低 | ✅ 适合压测 |
| **Response Time Graph** | 中 | 低 | 可长时间使用 |
| **Backend Listener** | 低 | 低 | ✅ 推荐生产压测 |
| **Simple Data Writer** | 低 | 低 | ✅ 原始数据保存 |
| **Generate Summary Results** | 极低 | 极低 | ✅ 命令行压测 |

> ⚠️ **关键建议**：生产压测时禁用 View Results Tree 和 Graph Results，仅保留 Aggregate Report + Backend Listener。

## 9. 报告解读方法论

### 9.1 先看总览

```
1. 错误率 > 1% → 存在严重问题，优先排查
2. 错误率 < 0.1% → 继续分析响应时间
3. 吞吐量是否达到预期
```

### 9.2 再看趋势

```
1. 响应时间是否随运行时间上升 → 内存/连接泄漏
2. 响应时间是否有周期性尖刺 → GC 停顿
3. 响应时间是否随并发上升线性增长 → 正常
4. 响应时间是否随并发上升指数增长 → 到达瓶颈
```

### 9.3 最后看分布

```
1. 平均值 ≈ 中位数 → 分布均匀
2. 平均值 >> 中位数 → 存在长尾（关注 99% Line）
3. p99 / p50 > 5 → 长尾严重，需要优化
```

## 10. 常见问题排查

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| **Dashboard 生成失败** | JTL 文件为空或损坏 | 检查 `-l` 文件，确认压测正常完成 |
| **Grafana 无数据** | InfluxDB 连接失败 | 检查 influxdbUrl，确认 InfluxDB 可访问 |
| **Graph Results 空白** | 未勾选数据写入 | 确认采样器正常执行 |
| **View Results Tree 无响应体** | 响应体过大被截断 | 增大 `view.results.tree.max_size` |
| **Dashboard 中文乱码** | 字体缺失 | 配置 `jmeter.reportgenerator.exporter.html.extra_libs` |
