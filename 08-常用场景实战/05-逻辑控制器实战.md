# 05 - 逻辑控制器实战

> **难度：★★★☆☆** | **适用版本：JMeter 5.6.3** | **预计阅读：25分钟**

---

## 1. 场景概述

逻辑控制器让你能像编写程序一样控制测试流程：条件分支、循环遍历、比例控制、事务统计等。本章通过 8 个实战场景，系统讲解常用逻辑控制器。

**你将学到：**
- If Controller 条件分支
- While Controller 循环等待
- ForEach Controller 遍历变量
- Transaction Controller 事务统计
- Throughput Controller 比例分配
- Switch Controller 多路选择
- Loop Controller 固定循环
- Runtime Controller 时间控制

## 2. If Controller（条件分支）

### 2.1 基本配置

| 参数 | 说明 |
|------|------|
| Condition (default JavaScript) | 条件表达式 |
| Interpret Condition as Variable Expression? | ✓（推荐：用变量表达式） |
| Evaluate for all children? | 是否对每个子元素都评估 |

> **推荐：** 勾选 "Interpret Condition as Variable Expression?"，然后使用 `${变量}` 或函数表达式。

### 2.2 条件表达式写法

| 表达式 | 说明 |
|--------|------|
| `${code}` == `"200"` | 变量等于字符串 |
| `${code}` != `"200"` | 变量不等于 |
| `${__jexl3(${code} == 200)}` | JEXL3 数字比较 |
| `${__jexl3(${count} > 10)}` | 大于判断 |
| `"${status}" == "paid"` | 字符串比较 |
| `${__jexl3("${token}" != "")}` | 判断变量非空 |
| `!${JMeterThread.last_sample_ok}` | 上一个采样失败 |

### 2.3 实战：根据响应结果分支处理

**场景：** 登录可能成功或失败，根据结果执行不同操作。

```
POST - 登录
├── JSON Extractor → code = $.code
├── If Controller (条件: "${code}" == "200")
│   ├── JSON Extractor → token = $.data.token
│   ├── GET - 获取用户信息
│   └── POST - 创建订单
└── If Controller (条件: "${code}" != "200")
    ├── JSR223 Sampler: log.warn("登录失败: " + prev.getResponseDataAsString())
    └── Flow Control Action: Stop Thread
```

### 2.4 实战：动态跳过请求

**场景：** 部分用户不需要执行某些步骤。

```
CSV Data Set Config (变量: username,role,skipPayment)

If Controller (条件: "${skipPayment}" != "true")
├── POST - 支付
└── ...
```

### 2.5 条件表达式注意事项

| 问题 | 正确写法 | 错误写法 |
|------|----------|----------|
| 变量可能未定义 | `${__jexl3("${var}" != "" && ${var} > 0)}` | `${var} > 0` |
| 字符串比较 | `"${status}" == "ok"` | `${status} == ok` |
| 逻辑与 | `${__jexl3(${a} > 0 && ${b} < 10)}` | `${a}>0 && ${b}<10` |
| 逻辑或 | `${__jexl3(${a} == 1 \|\| ${b} == 2)}` | - |

## 3. While Controller（循环等待）

### 3.1 基本配置

| 参数 | 值 | 说明 |
|------|-----|------|
| Condition | 表达式/函数/变量 | 为 true 时继续循环 |
| 空条件 | 循环到最后一个子采样器失败 | 类似 `while(true)` |

### 3.2 实战：轮询等待异步任务完成

**场景：** 提交异步任务后，轮询检查任务状态直到完成。

```
POST - 提交异步任务
├── JSON Extractor → taskId = $.data.taskId
├── While Controller (条件: ${__jexl3("${taskStatus}" != "completed" && "${taskStatus}" != "failed")})
│   ├── Constant Timer (间隔: 2000ms)
│   ├── GET - 查询任务状态
│   │   └── Path: /api/tasks/${taskId}/status
│   └── JSON Extractor → taskStatus = $.data.status
└── If Controller (条件: "${taskStatus}" == "failed")
    └── JSR223 Sampler: log.error("任务失败: ${taskId}")
```

### 3.3 实战：分页获取全部数据

**场景：** API 分页返回数据，需要循环获取所有页。

```
User Defined Variables:
  page = 1
  totalPages = 999

While Controller (条件: ${__jexl3(${page} <= ${totalPages})})
├── GET - 获取分页数据
│   └── Path: /api/items?page=${page}&size=50
├── JSON Extractor
│   ├── totalPages = $.data.totalPages (仅首次提取)
│   └── items = $.data.items
├── JSR223 PostProcessor (Groovy)
│   └── vars.put("page", String.valueOf((vars.get("page") as int) + 1))
└── JSR223 Sampler: 处理当前页数据
```

### 3.4 防止无限循环

```groovy
// 在 While Controller 的第一个子元素中添加
def loopCount = vars.get("loopCount") ?: "0"
def count = loopCount as int
if (count > 100) {
    log.error("While 循环超过100次，强制退出")
    vars.put("forceStop", "true")
    // 设置条件变量使 While 退出
    vars.put("taskStatus", "failed")
}
vars.put("loopCount", String.valueOf(count + 1))
```

## 4. ForEach Controller（遍历变量）

### 4.1 基本配置

| 参数 | 说明 |
|------|------|
| Input variable prefix | 输入变量前缀（如 `item`） |
| Start index for loop | 起始索引（通常为 0 或 1） |
| End index for loop | 结束索引 |
| Output variable name | 输出变量名 |
| Add "_" before number? | 是否在数字前加下划线 |

### 4.2 变量命名规则

假设有变量：
```
item_1 = apple
item_2 = banana
item_3 = cherry
item_matchNr = 3
```

**配置：**

| 参数 | 值 |
|------|-----|
| Input variable prefix | `item` |
| Start index | `1` |
| End index | `${item_matchNr}` |
| Output variable name | `currentItem` |
| Add "_" before number? | ✓ |

**循环结果：**
- 第1次：`${currentItem}` = `apple`
- 第2次：`${currentItem}` = `banana`
- 第3次：`${currentItem}` = `cherry`

### 4.3 实战：批量处理搜索结果

```
GET - 搜索商品
├── JSON Extractor → productId = $.data.products[*].id (Match No: -1)
├── ForEach Controller
│   ├── Input prefix: productId
│   ├── Output variable: currentProductId
│   ├── GET - 获取商品详情
│   │   └── Path: /api/products/${currentProductId}
│   └── POST - 加入购物车
│       └── Body: {"productId":${currentProductId}}
└── POST - 提交订单
```

## 5. Transaction Controller（事务统计）

### 5.1 基本配置

| 参数 | 说明 |
|------|------|
| Generate parent sample | ✓：生成父采样器（推荐） |
| Include duration of timer | 是否包含定时器时间（默认否） |

### 5.2 实战：统计完整业务事务

**场景：** 统计"下单"业务的端到端响应时间。

```
Transaction Controller: 下单流程
├── GET - 查看商品详情
├── POST - 加入购物车
├── POST - 创建订单
├── POST - 支付
└── GET - 查看订单确认
```

> 在 Aggregate Report 中会看到名为 "下单流程" 的汇总行，包含 5 个子步骤的总响应时间。

### 5.3 Generate parent sample 对比

| 选项 | Aggregate Report 中的行为 |
|------|--------------------------|
| **勾选（推荐）** | 仅显示事务汇总行，子请求统计不单独计入 |
| **不勾选** | 显示事务汇总行 + 所有子请求行 |

## 6. Throughput Controller（比例分配）

### 6.1 基本配置

| 参数 | 说明 |
|------|------|
| Percent Executions | 执行百分比 |
| Total Executions | 总执行次数 |
| Per User | 按线程还是按总数 |

### 6.2 实战：模拟真实流量分布

**场景：** 80% 浏览 + 15% 搜索 + 5% 下单。

```
Thread Group (100 threads)
├── Throughput Controller (80%)
│   └── GET - 浏览首页
├── Throughput Controller (15%)
│   ├── GET - 搜索商品
│   └── GET - 商品详情
└── Throughput Controller (5%)
    ├── POST - 加入购物车
    ├── POST - 创建订单
    └── POST - 支付
```

### 6.3 注意事项

- 百分比总和不必等于 100%
- `Per User` 勾选后，每个线程独立计算百分比
- 多个 Throughput Controller 是**顺序执行**的，不会并发

## 7. Switch Controller（多路选择）

### 7.1 基本配置

| 参数 | 值 |
|------|-----|
| Switch Value | 要执行子元素的索引（从0开始）或名称 |

### 7.2 实战：根据环境切换行为

```
User Defined Variables:
  env = ${__P(env,dev)}

Switch Controller (Switch Value: ${env})
├── Simple Controller: dev (索引0)
│   └── HTTP Request: https://dev-api.example.com/test
├── Simple Controller: staging (索引1)
│   └── HTTP Request: https://staging-api.example.com/test
└── Simple Controller: prod (索引2)
    └── HTTP Request: https://api.example.com/test
```

> 命令行：`jmeter -n -t test.jmx -Jenv=staging` 将执行 staging 分支。

## 8. Loop Controller（固定循环）

### 8.1 基本配置

| 参数 | 值 |
|------|-----|
| Loop Count | 循环次数（Forever = 勾选无限循环） |

### 8.2 实战：重试机制

```
POST - 提交订单
├── JSON Extractor → orderStatus = $.data.status
├── If Controller (条件: "${orderStatus}" != "success")
│   ├── Loop Controller (Loop Count: 3)
│   │   ├── Constant Timer (2000ms)
│   │   ├── POST - 重试提交
│   │   └── JSON Extractor → orderStatus = $.data.status
│   │   └── If Controller (条件: "${orderStatus}" == "success")
│   │       └── Flow Control Action: Break Loop
│   └── If Controller (条件: "${orderStatus}" != "success")
│       └── JSR223 Sampler: log.error("订单提交失败，已重试3次")
```

## 9. Runtime Controller（时间控制）

### 9.1 基本配置

| 参数 | 值 |
|------|-----|
| Runtime (seconds) | 运行时长（秒） |

### 9.2 适用场景

> **注意：** Runtime Controller 控制的是单个线程内子元素的执行时间，不是整个测试时长。控制总时长应使用 Thread Group 的 Scheduler 或命令行 `-Jduration`。

### 9.3 实战：控制子流程执行时间

```
Runtime Controller (Runtime: 60秒)
├── GET - 轮询数据
└── Constant Timer (1000ms)
```

> 该线程会在 60 秒内不断轮询。

## 10. 综合实战：电商用户行为模拟

### 10.1 场景描述

模拟真实用户行为：大部分浏览、少量搜索、极少购买，且购买用户需要先登录。

### 10.2 测试计划结构

```
Test Plan: 电商用户行为模拟
├── CSV Data Set Config (变量: username,password)
├── HTTP Cookie Manager
├── HTTP Header Manager
│   └── Content-Type: application/json
├── Thread Group (100 threads, 60s ramp-up, 300s duration)
│   │
│   ├── GET - 首页 (所有用户)
│   │
│   ├── Throughput Controller (30%)
│   │   ├── GET - 搜索商品
│   │   ├── JSON Extractor → productIds = $.data.items[*].id
│   │   └── ForEach Controller (遍历搜索结果)
│   │       └── GET - 商品详情
│   │
│   ├── Throughput Controller (10%)
│   │   ├── Transaction Controller: 登录下单
│   │   │   ├── POST - 登录
│   │   │   │   └── JSON Extractor → token, userId
│   │   │   ├── GET - 商品详情
│   │   │   ├── POST - 加入购物车
│   │   │   ├── POST - 创建订单
│   │   │   │   └── JSON Extractor → orderId
│   │   │   ├── POST - 支付
│   │   │   └── GET - 订单确认
│   │   └── If Controller (条件: ${JMeterThread.last_sample_ok})
│   │       └── GET - 推荐商品
│   │
│   └── Throughput Controller (5%)
│       ├── GET - 个人中心
│       └── POST - 更新个人信息
│
├── View Results Tree
├── Aggregate Report
└── Summary Report
```

### 10.3 关键配置说明

| 组件 | 关键配置 | 说明 |
|------|----------|------|
| Throughput Controller (30%) | Percent: 30, Per User: ✓ | 30%线程执行搜索 |
| Throughput Controller (10%) | Percent: 10, Per User: ✓ | 10%线程执行购买 |
| Transaction Controller | Generate parent: ✓ | 统计端到端下单时间 |
| If Controller | `${JMeterThread.last_sample_ok}` | 下单成功才看推荐 |

## 11. 控制器选择指南

| 需求 | 推荐控制器 |
|------|-----------|
| 根据条件执行不同请求 | **If Controller** |
| 等待某个条件满足 | **While Controller** |
| 遍历变量列表 | **ForEach Controller** |
| 统计一组请求的总时间 | **Transaction Controller** |
| 按比例分配流量 | **Throughput Controller** |
| 根据参数切换分支 | **Switch Controller** |
| 固定次数循环 | **Loop Controller** |
| 固定时间循环 | **Runtime Controller** |
| 仅执行一次（初始化） | **Once Only Controller** |
| 随机执行一个子元素 | **Random Controller** |
| 随机顺序执行 | **Random Order Controller** |
| 控制并发临界区 | **Critical Section Controller** |
