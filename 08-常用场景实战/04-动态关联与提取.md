# 04 - 动态关联与提取

> **难度：★★★☆☆** | **适用版本：JMeter 5.6.3** | **预计阅读：25分钟**

---

## 1. 场景概述

动态关联（Correlation）是性能测试中最关键的技能之一。在一个真实的业务流程中，后续请求往往依赖前面请求的响应数据（如用户 ID、订单号、Token 等）。本章系统讲解 6 种提取方式。

**你将学到：**
- Regular Expression Extractor（正则提取）
- JSON Extractor（JSONPath 提取）
- JSON JMESPath Extractor（更强大的 JSON 查询）
- CSS Selector Extractor（HTML 页面提取）
- Boundary Extractor（边界提取）
- JSR223 PostProcessor（Groovy 自定义提取）
- 多级关联链：提取 → 引用 → 再提取

---

## 2. 提取器总览

| 提取器 | 适用场景 | 性能 | 易用性 |
|--------|----------|------|--------|
| **Regular Expression Extractor** | HTML/XML/文本/响应头 | ★★★★★ | ★★★☆☆ |
| **JSON Extractor** | JSON 响应 | ★★★★☆ | ★★★★☆ |
| **JSON JMESPath Extractor** | JSON 响应（复杂查询） | ★★★☆☆ | ★★★★★ |
| **CSS Selector Extractor** | HTML 页面 | ★★★★☆ | ★★★★☆ |
| **Boundary Extractor** | 简单文本/固定格式 | ★★★★★ | ★★★★★ |
| **JSR223 PostProcessor** | 任意复杂逻辑 | ★★★☆☆ | ★★☆☆☆ |

## 3. Regular Expression Extractor（正则提取）

### 3.1 基本配置

右键采样器 → Add → Post Processors → **Regular Expression Extractor**

| 参数 | 说明 |
|------|------|
| Apply to | 应用于哪个范围 |
| Field to check | 检查哪个字段（Body/Headers/URL/Response Code等） |
| Reference Name | 变量名前缀 |
| Regular Expression | 正则表达式 |
| Template | 模板（`$1$` 取第一个捕获组） |
| Match No. | 匹配序号（0=随机，1=第一个，-1=全部） |
| Default Value | 匹配失败时的默认值 |

### 3.2 实战：提取 HTML 中的隐藏字段

**响应内容：**

```html
<input type="hidden" name="authenticity_token" value="abc123xyz456" />
```

**提取器配置：**

| 参数 | 值 |
|------|-----|
| Reference Name | `authToken` |
| Regular Expression | `name="authenticity_token" value="(.+?)"` |
| Template | `$1$` |
| Match No. | `1` |
| Default Value | `NOT_FOUND` |

**引用：** `${authToken}`

### 3.3 实战：提取响应头中的值

**响应头：**

```
Set-Cookie: session_id=sess_abc123; Path=/; HttpOnly
```

**提取器配置：**

| 参数 | 值 |
|------|-----|
| Reference Name | `sessionId` |
| Regular Expression | `session_id=(.+?);` |
| Template | `$1$` |
| Field to check | `Response Headers` |

### 3.4 实战：提取多个匹配结果

**响应内容：**

```html
<li>Item 1: apple</li>
<li>Item 2: banana</li>
<li>Item 3: cherry</li>
```

**提取器配置：**

| 参数 | 值 |
|------|-----|
| Reference Name | `item` |
| Regular Expression | `<li>Item \d+: (.+?)</li>` |
| Template | `$1$` |
| Match No. | `-1`（匹配全部） |

**生成的变量：**

| 变量 | 值 |
|------|-----|
| `${item_matchNr}` | `3` |
| `${item_1}` | `apple` |
| `${item_2}` | `banana` |
| `${item_3}` | `cherry` |

> **提示：** `_matchNr` 变量记录匹配总数，配合 ForEach Controller 遍历所有结果。

## 4. JSON Extractor（JSONPath 提取）

### 4.1 基本配置

右键采样器 → Add → Post Processors → **JSON Extractor**

| 参数 | 说明 |
|------|------|
| Names of created variables | 变量名，多个用分号分隔 |
| JSON Path expressions | JSONPath 表达式，多个用分号分隔 |
| Match No. | -1=全部，0=随机，N=第N个 |
| Compute concatenation var | 是否创建 `_ALL` 拼接变量 |
| Default Values | 默认值，多个用分号分隔 |

### 4.2 JSONPath 语法速查

| 表达式 | 说明 | 示例 |
|--------|------|------|
| `$` | 根节点 | - |
| `.key` | 取子节点 | `$.name` |
| `[0]` | 数组索引 | `$.users[0]` |
| `[-1]` | 最后一个元素 | `$.users[-1]` |
| `[*]` | 所有元素 | `$.users[*].name` |
| `..key` | 递归搜索 | `$..email` |
| `[?(@.key==val)]` | 条件过滤 | `$[?(@.age>18)]` |
| `[0:3]` | 切片 | `$.users[0:3]` |

### 4.3 实战：提取单个值

**响应 JSON：**

```json
{
    "code": 200,
    "data": {
        "userId": 12345,
        "username": "john_doe",
        "token": "eyJhbGciOiJIUzI1NiIs..."
    },
    "message": "success"
}
```

**提取器配置：**

| 参数 | 值 |
|------|-----|
| Names of created variables | `userId;username;token` |
| JSON Path expressions | `$.data.userId;$.data.username;$.data.token` |
| Default Values | `0;unknown;NO_TOKEN` |

**生成的变量：**
- `${userId}` = `12345`
- `${username}` = `john_doe`
- `${token}` = `eyJhbGciOiJIUzI1NiIs...`

### 4.4 实战：提取数组

**响应 JSON：**

```json
{
    "users": [
        {"id": 1, "name": "Alice", "email": "alice@example.com"},
        {"id": 2, "name": "Bob", "email": "bob@example.com"},
        {"id": 3, "name": "Charlie", "email": "charlie@example.com"}
    ]
}
```

**提取所有用户名：**

| 参数 | 值 |
|------|-----|
| Names of created variables | `userName` |
| JSON Path expressions | `$.users[*].name` |
| Match No. | `-1` |

**生成的变量：**

| 变量 | 值 |
|------|-----|
| `${userName_matchNr}` | `3` |
| `${userName_1}` | `Alice` |
| `${userName_2}` | `Bob` |
| `${userName_3}` | `Charlie` |
| `${userName_ALL}` | `Alice,Bob,Charlie` |

### 4.5 实战：条件过滤

**提取邮箱为 `bob@example.com` 的用户 ID：**

| 参数 | 值 |
|------|-----|
| Names of created variables | `bobId` |
| JSON Path expressions | `$.users[?(@.email=='bob@example.com')].id` |

## 5. JSON JMESPath Extractor

### 5.1 与 JSONPath 的区别

JMESPath 更强大，支持复杂的数据转换和聚合。

### 5.2 JMESPath 语法速查

| 表达式 | 说明 |
|--------|------|
| `users[*].name` | 所有用户名 |
| `users[?age > \`18\`]` | 过滤（注意反引号） |
| `users | sort_by(@, &age)` | 排序 |
| `length(users)` | 数组长度 |
| `max(users[*].age)` | 最大值 |
| `join(', ', users[*].name)` | 拼接 |

### 5.3 实战：复杂条件查询

**响应 JSON：**

```json
{
    "orders": [
        {"id": "A001", "amount": 150, "status": "paid"},
        {"id": "A002", "amount": 80, "status": "pending"},
        {"id": "A003", "amount": 320, "status": "paid"},
        {"id": "A004", "amount": 50, "status": "paid"}
    ]
}
```

**提取已支付且金额大于 100 的订单 ID：**

| 参数 | 值 |
|------|-----|
| Names of created variables | `highValueOrders` |
| JMESPath expressions | `orders[?status == 'paid' && amount > \`100\`].id` |
| Default Values | `NONE` |

**结果：** `${highValueOrders_ALL}` = `A001,A003`

## 6. CSS Selector Extractor（HTML 提取）

### 6.1 基本配置

| 参数 | 说明 |
|------|------|
| Implementation | `JODD`（推荐）或 `JSoup` |
| CSS Selector Expression | CSS 选择器 |
| Attribute | 要提取的属性名（`content`/`href`/`value` 等） |
| Reference Name | 变量名 |
| Match No. | 匹配序号 |

### 6.2 常用 CSS 选择器

| 选择器 | 说明 | 示例 |
|--------|------|------|
| `#id` | 按 ID 选择 | `#login-form` |
| `.class` | 按 class 选择 | `.user-name` |
| `tag` | 按标签选择 | `input` |
| `[attr]` | 按属性选择 | `[name=_csrf]` |
| `[attr=val]` | 按属性值选择 | `[type=hidden]` |
| `parent > child` | 直接子元素 | `form > input` |
| `parent child` | 后代元素 | `div a` |

### 6.3 实战：提取表单隐藏字段

**HTML：**

```html
<form id="checkout-form">
    <input type="hidden" name="order_id" value="ORD-98765" />
    <input type="hidden" name="signature" value="a1b2c3d4" />
</form>
```

**提取 order_id：**

| 参数 | 值 |
|------|-----|
| CSS Selector Expression | `input[name=order_id]` |
| Attribute | `value` |
| Reference Name | `orderId` |
| Default Value | `NOT_FOUND` |

**提取 signature：**

| 参数 | 值 |
|------|-----|
| CSS Selector Expression | `input[name=signature]` |
| Attribute | `value` |
| Reference Name | `signature` |

## 7. Boundary Extractor（边界提取）

### 7.1 适用场景

当响应格式简单固定，使用边界提取比正则更快更简单。

### 7.2 配置

| 参数 | 说明 |
|------|------|
| Reference Name | 变量名 |
| Left Boundary | 左边界字符串 |
| Right Boundary | 右边界字符串 |
| Match No. | 匹配序号 |
| Default Value | 默认值 |

### 7.3 实战

**响应内容：**

```
<input type="hidden" id="requestVerificationToken" value="CfDJ8A..." />
```

**提取 Token：**

| 参数 | 值 |
|------|-----|
| Reference Name | `verificationToken` |
| Left Boundary | `value="` |
| Right Boundary | `"` |
| Match No. | `1` |

> **注意：** 如果左右边界在多处出现，使用 Match No. 指定具体匹配位置。

## 8. JSR223 PostProcessor（自定义提取）

### 8.1 适用场景

当内置提取器无法满足需求时（如需要解密、Base64 解码、复杂计算等）。

### 8.2 实战：解密并提取 Token

```groovy
import java.util.Base64
import groovy.json.JsonSlurper

// 获取响应数据
def response = prev.getResponseDataAsString()

// Base64 解码
def decoded = new String(Base64.getDecoder().decode(response))

// 解析 JSON
def json = new JsonSlurper().parseText(decoded)

// 提取并存储变量
vars.put("userId", json.data.userId.toString())
vars.put("token", json.data.token)
vars.put("expiresAt", json.data.expiresAt)

// 计算过期时间（秒）
def now = System.currentTimeMillis() / 1000
def ttl = (json.data.expiresAt as long) - now
vars.put("tokenTTL", ttl.toString())

log.info("Token 提取成功，剩余有效期: ${ttl}秒")
```

### 8.3 实战：根据响应头动态选择变量

```groovy
def contentType = prev.getContentType()
def responseData = prev.getResponseDataAsString()

if (contentType.contains("application/json")) {
    def json = new groovy.json.JsonSlurper().parseText(responseData)
    vars.put("extractedId", json.id.toString())
} else if (contentType.contains("text/xml")) {
    def xml = new groovy.xml.XmlSlurper().parseText(responseData)
    vars.put("extractedId", xml.data.id.text())
} else {
    // 用正则兜底
    def matcher = (responseData =~ /id[":]\s*(\d+)/)
    vars.put("extractedId", matcher[0] ? matcher[0][1] : "NOT_FOUND")
}
```

## 9. 多级关联链实战

### 9.1 场景：完整电商下单流程

```
登录 → 浏览商品 → 加入购物车 → 创建订单 → 支付
```

每一步都依赖上一步的输出：

```
POST /login
  └── JSON Extractor → token, userId

GET /products?category=electronics
  └── JSON Extractor → productId_1, productId_2

POST /cart/add
  ├── Header: Authorization: Bearer ${token}
  ├── Body: {"userId":${userId},"productId":${productId_1}}
  └── JSON Extractor → cartId

POST /orders
  ├── Header: Authorization: Bearer ${token}
  ├── Body: {"cartId":${cartId},"userId":${userId}}
  └── JSON Extractor → orderId, totalAmount

POST /payments
  ├── Header: Authorization: Bearer ${token}
  └── Body: {"orderId":${orderId},"amount":${totalAmount}}
```

### 9.2 变量传递链可视化

```
${token} ──────────────────────────────────────────────────────┐
        └──→ ${userId} ──→ ${cartId} ──→ ${orderId} ──→ ${paymentId}
                                    └──→ ${totalAmount} ──┘
```

> **最佳实践：** 使用 Transaction Controller 包裹整条链路，获得端到端业务响应时间。

## 10. 提取失败处理

### 10.1 设置默认值

所有提取器都支持 Default Value，设置合理的默认值便于排查：

```
Default Value: NOT_FOUND / NO_TOKEN / -1
```

### 10.2 使用 If Controller 处理异常

```
If Controller (条件: "${token}" == "NO_TOKEN")
├── JSR223 Sampler: 记录错误日志
├── Flow Control Action: 停止当前线程
└── ...
```

### 10.3 使用 Result Status Action Handler

右键采样器 → Add → Post Processors → **Result Status Action Handler**

| 参数 | 值 | 说明 |
|------|-----|------|
| Action on error | `Stop Test Now` | 立即停止测试 |

## 11. 常见问题排查

### 11.1 变量值为默认值

**排查步骤：**
1. 检查提取器的 Field to check / Apply to 是否正确
2. 用 View Results Tree 查看实际响应内容
3. 在 View Results Tree 的 RegExp Tester 中测试表达式
4. 检查响应是否包含预期内容（可能被重定向或返回错误页）

### 11.2 正则表达式不匹配

**解决：**
1. 使用 `(.+?)` 而非 `(.+)`（非贪婪匹配）
2. 注意转义特殊字符：`.` `*` `?` `[` `(` `{` `\`
3. 考虑换行符：在表达式前加 `(?s)` 让 `.` 匹配换行
4. 使用 View Results Tree → RegExp Tester 实时测试

### 11.3 JSONPath 不匹配

**解决：**
1. 使用 View Results Tree → JSON Path Tester 实时测试
2. 确认 JSON 响应格式（可能是 `data.data.token` 嵌套）
3. 注意根节点：响应直接是数组时用 `$[0].key`

### 11.4 变量在后续请求中为空

**解决：**
1. 确认提取器是目标采样器的**子元素**（层级正确）
2. 确认采样器按预期顺序执行
3. 使用 Debug Sampler 查看变量值
