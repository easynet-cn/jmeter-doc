# 02 - 参数化与数据驱动测试

> **难度：★★☆☆☆** | **适用版本：JMeter 5.6.3** | **预计阅读：20分钟**

---

## 1. 场景概述

在实际测试中，使用固定数据跑测试没有意义。参数化让每次迭代使用不同数据，模拟真实用户行为。本章覆盖 5 种参数化方式及其适用场景。

**你将学到：**
- CSV Data Set Config 完整配置（4种共享模式）
- User Defined Variables 定义全局常量
- Random Variable 生成随机参数
- Counter 生成自增序号
- 命令行参数传递
- 多列 CSV 组合参数化

---

## 2. 方式一：CSV Data Set Config（最常用）

### 2.1 场景：多用户登录测试

假设需要模拟 10 个不同用户登录系统。

#### 2.1.1 准备 CSV 文件

创建 `testdata/users.csv`：

```csv
username,password,role
admin,admin123,ADMIN
user1,pass001,USER
user2,pass002,USER
user3,pass003,USER
user4,pass004,USER
user5,pass005,USER
user6,pass006,USER
user7,pass007,USER
user8,pass008,USER
user9,pass009,USER
```

> **注意：** 第一行是列头，配置时勾选 `Ignore first line` 跳过。

#### 2.1.2 配置 CSV Data Set Config

右键 Thread Group → Add → Config Element → **CSV Data Set Config**

| 参数 | 值 | 说明 |
|------|-----|------|
| Filename | `testdata/users.csv` | 相对路径（相对于 .jmx 文件） |
| File Encoding | `UTF-8` | 避免中文乱码 |
| Variable Names | `username,password,role` | 按列顺序命名，逗号分隔 |
| Ignore first line | `True` | 跳过表头行 |
| Delimiter | `,` | 列分隔符 |
| Allow quoted data? | `False` | 不使用引号包裹 |
| Recycle on EOF? | `True` | 读到文件末尾后重新循环 |
| Stop thread on EOF? | `False` | 不停止线程（与Recycle配合） |
| Sharing mode | `All threads` | 所有线程共享数据 |

#### 2.1.3 引用变量

在 HTTP Request 的 Body Data 中使用：

```json
{
    "username": "${username}",
    "password": "${password}",
    "role": "${role}"
}
```

或在 Parameters 标签页中：

| Name | Value |
|------|-------|
| `username` | `${username}` |
| `password` | `${password}` |

#### 2.1.4 线程组配置

| 参数 | 值 | 说明 |
|------|-----|------|
| Number of Threads | `10` | 对应 10 个用户 |
| Loop Count | `1` | 每个用户登录一次 |

> **执行逻辑：** 10 个线程各取一行，覆盖全部 10 条数据。

---

### 2.2 四种共享模式详解

| 模式 | 行为 | 适用场景 |
|------|------|----------|
| **All threads**（默认） | 所有线程组的所有线程共享同一个文件指针 | 全局唯一数据（如唯一用户名） |
| **Current thread group** | 每个线程组独立维护文件指针 | 多线程组各自使用不同数据集 |
| **Current thread** | 每个线程独立拥有完整数据集 | 每个线程需要遍历全部数据 |
| **Identifier** | 共享相同标识符的线程共享指针 | 复杂分组场景 |

#### 场景对比示例

**场景A：10 线程 × 1 循环，10 行数据**

| 模式 | 结果 |
|------|------|
| All threads | 每线程取1行，10行全部用完 |
| Current thread | 每线程取1行，10线程都取第1行 |

**场景B：5 线程 × 3 循环，10 行数据**

| 模式 | 结果 |
|------|------|
| All threads + Recycle=true | 5×3=15次，行1-10用完再循环1-5 |
| Current thread + Recycle=true | 每线程循环3次取行1-3 |

---

### 2.3 何时停止线程

| 配置组合 | 行为 |
|----------|------|
| Recycle=true, Stop=false | 数据循环使用，永不停止（默认） |
| Recycle=false, Stop=true | 数据用完即停止线程 |
| Recycle=false, Stop=false | 数据用完后每次取 `<EOF>` |
| Recycle=true, Stop=true | **无效配置**（会被忽略） |

> **推荐：** 压测时使用默认（循环），数据驱动功能测试时使用 `Recycle=false, Stop=true`。

## 3. 方式二：User Defined Variables（全局常量）

### 3.1 场景：定义环境配置

右键 Test Plan → Add → Config Element → **User Defined Variables**

| Name | Value | 说明 |
|------|-------|------|
| `BASE_URL` | `jsonplaceholder.typicode.com` | 服务器地址 |
| `API_PREFIX` | `/api/v1` | API 版本前缀 |
| `TIMEOUT` | `30000` | 超时时间（毫秒） |

引用方式：`${BASE_URL}`, `${API_PREFIX}`

**特点：**
- 在测试计划启动时就初始化
- 整个测试期间保持不变
- 不会被 CSV Data Set Config 等覆盖
- 适合定义环境常量、版本号、超时等

---

## 4. 方式三：Random Variable（随机参数）

### 4.1 场景：生成随机手机号、订单号

右键 Thread Group → Add → Config Element → **Random Variable**

| 参数 | 值 | 说明 |
|------|-----|------|
| Variable Name | `randomPhone` | 变量名 |
| Minimum Value | `13800000000` | 最小值 |
| Maximum Value | `13899999999` | 最大值 |
| Output Format | （留空） | 不格式化 |
| Per Thread | `False` | 所有线程共享随机序列 |

引用：`${randomPhone}`

### 4.2 场景：生成随机字符串

使用 `__RandomString` 函数更灵活：

```
${__RandomString(8,abcdefghijklmnopqrstuvwxyz,randomStr)}
```

参数说明：
- `8` - 字符串长度
- `abcdefghijklmnopqrstuvwxyz` - 字符集
- `randomStr` - 存储变量名

---

## 5. 方式四：Counter（自增序号）

### 5.1 场景：生成唯一请求序号

右键 Thread Group → Add → Config Element → **Counter**

| 参数 | 值 | 说明 |
|------|-----|------|
| Starting value | `1000` | 起始值 |
| Increment | `1` | 步长 |
| Maximum value | `9999` | 最大值 |
| Number format | `0000` | 格式化为4位（0000→1000） |
| Reference Name | `requestId` | 变量名 |
| Track counter independently for each user | `False` | 全局递增 |

引用：`${requestId}`

> 当 Track counter independently = True 时，每个线程拥有独立计数器。

## 6. 方式五：命令行参数传递

### 6.1 使用 `-J` 参数

```bash
jmeter -n -t test.jmx -Jthreads=50 -Jduration=300 -Jenv=staging
```

在测试计划中引用：`${__P(threads,10)}`, `${__P(env,dev)}`

> `__P(property, default)` 函数：获取属性值，不存在时使用默认值。

### 6.2 使用 `-G` 参数（分布式）

```bash
jmeter -n -t test.jmx -R server1,server2 -Gthreads=50
```

> `-G` 会将属性发送到所有远程服务器，`-J` 只在本地生效。

### 6.3 常用命令行参数化脚本

```bash
#!/bin/bash
# run_jmeter.sh
THREADS=${1:-10}
DURATION=${2:-60}
ENV=${3:-dev}

jmeter -n \
  -t api_test.jmx \
  -Jthreads=$THREADS \
  -Jduration=$DURATION \
  -Jenv=$ENV \
  -l results/${ENV}_${THREADS}vu_$(date +%Y%m%d_%H%M%S).csv \
  -e -o reports/${ENV}_${THREADS}vu_$(date +%Y%m%d_%H%M%S}
```

## 7. 综合实战：数据驱动 API 测试

### 7.1 场景

模拟 20 个用户，每个用户创建 3 篇文章，文章标题和内容从 CSV 读取。

### 7.2 CSV 文件 `testdata/articles.csv`

```csv
title,body,tag
"JMeter 入门指南","本文介绍 JMeter 的基本用法","tutorial"
"性能测试最佳实践","详解性能测试的策略与方法","best-practice"
"分布式压测实战","从零搭建分布式压测环境","advanced"
"REST API 测试技巧","分享 REST API 测试的实用技巧","api"
"负载测试常见误区","避免负载测试中的常见错误","tips"
```

### 7.3 测试计划结构

```
Test Plan: 数据驱动 API 测试
├── User Defined Variables
│   └── BASE_URL = jsonplaceholder.typicode.com
├── HTTP Request Defaults
│   └── Server: ${BASE_URL}
├── HTTP Header Manager
│   └── Content-Type: application/json
├── Thread Group (20 threads, 3 loops)
│   ├── CSV Data Set Config
│   │   └── Filename: testdata/articles.csv
│   │   └── Variables: title,body,tag
│   ├── Counter (requestId: 1000-9999)
│   ├── POST - 创建文章
│   │   ├── Body Data: {"title":"${title}","body":"${body}"}
│   │   └── JSON Extractor → postId = $.id
│   ├── GET - 验证文章
│   │   └── Path: /posts/${postId}
│   ├── JSON Assertion (验证标题匹配)
│   │   └── JSONPath: $.title  Expected: ${title}
│   ├── View Results Tree
│   └── Aggregate Report
```

### 7.4 关键配置说明

**Thread Group 配置：**

| 参数 | 值 | 说明 |
|------|-----|------|
| Threads | `20` | 20 个并发用户 |
| Ramp-up | `10` | 10 秒内逐步启动 |
| Loop Count | `3` | 每用户创建 3 篇文章 |

**CSV Data Set Config：**

| 参数 | 值 |
|------|-----|
| Filename | `testdata/articles.csv` |
| Variable Names | `title,body,tag` |
| Recycle on EOF? | `True` |
| Stop thread on EOF? | `False` |
| Sharing mode | `All threads` |

**执行结果：** 20 线程 × 3 循环 = 60 次请求，CSV 有 5 行数据，循环 12 遍。

## 8. 变量优先级

当多个地方定义了同名变量时，优先级从低到高：

```
1. User Defined Variables（Test Plan 级）      ← 最低
2. User Defined Variables（Thread Group 级）
3. CSV Data Set Config
4. User Parameters（前置处理器）
5. 提取器（Regex/JSON Extractor 等）           ← 最高
```

> **最佳实践：** 避免同名变量。使用有意义的前缀区分，如 `csv_username`、`extract_token`。

## 9. 调试变量

### 9.1 Debug Sampler

右键 Thread Group → Add → Sampler → **Debug Sampler**

| 参数 | 值 |
|------|-----|
| JMeter Properties | `True` |
| JMeter Variables | `True` |
| System Properties | `False` |

> 配合 View Results Tree 查看所有变量当前值。

### 9.2 使用 __log 函数

```
${__log(当前用户: ${username}, 密码: ${password})}
```

在 JMeter 控制台输出日志，便于调试。

## 10. 常见问题排查

### 10.1 CSV 文件找不到

**现象：** 请求中变量显示为 `${username}` 未替换。

**解决：**
1. 检查 CSV 文件路径：相对路径相对于 .jmx 文件所在目录
2. 检查 File Encoding 是否匹配文件编码
3. 查看 jmeter.log 中的错误信息

### 10.2 变量值为 `<EOF>`

**现象：** 变量显示 `<EOF>`。

**原因：** CSV 数据已读完，且 `Stop thread on EOF? = False`、`Recycle on EOF? = False`。

**解决：** 设置 `Recycle on EOF? = True` 或 `Stop thread on EOF? = True`。

### 10.3 并发线程取到相同数据

**现象：** 多个线程取到同一行 CSV 数据。

**原因：** Sharing mode 设置不当。

**解决：** 确保使用 `All threads` 模式，或改用 `Current thread` 模式（如果需要每个线程独立）。

### 10.4 中文 CSV 乱码

**解决：** CSV 文件保存为 UTF-8 编码，CSV Data Set Config 中设置 `File Encoding: UTF-8`。
