# 06 - 定时器

定时器用于在请求之间引入延迟，模拟真实用户行为。多个定时器的时间会累加。

---

## Constant Timer

固定延迟时间。

| 参数 | 说明 |
|------|------|
| **Thread Delay (ms)** | 固定延迟（毫秒） |

---

## Uniform Random Timer

均匀分布随机延迟。

| 参数 | 说明 |
|------|------|
| **Random Delay Maximum (ms)** | 最大随机延迟 |
| **Constant Delay Offset (ms)** | 固定延迟偏移 |

实际延迟 = 固定偏移 + 0 到最大随机值之间的随机数

---

## Gaussian Random Timer

高斯（正态）分布随机延迟。

| 参数 | 说明 |
|------|------|
| **Deviation (ms)** | 标准差 |
| **Constant Delay Offset (ms)** | 固定延迟偏移 |

实际延迟 = 固定偏移 + 高斯分布随机值

---

## Poisson Random Timer

泊松分布随机延迟。

| 参数 | 说明 |
|------|------|
| **Lambda (ms)** | 泊松分布的 Lambda 参数 |
| **Constant Delay Offset (ms)** | 固定延迟偏移 |

---

## Constant Throughput Timer

按恒定吞吐量控制请求速率。

| 参数 | 说明 |
|------|------|
| **Target Throughput (samples/min)** | 目标吞吐量（每分钟采样数） |
| **Calculate based on** | 计算基准：this thread only / all active threads / all active threads in current group / all active threads (shared) |

---

## Precise Throughput Timer

精确的吞吐量控制定时器。

| 参数 | 说明 |
|------|------|
| **Target Throughput** | 目标吞吐量 |
| **Throughput Period (seconds)** | 吞吐量周期 |
| **Test Duration (seconds)** | 测试持续时间 |
| **Number of threads in the batch** | 批次线程数 |

---

## Synchronizing Timer

同步定时器，等待指定数量的线程到达后一起释放。

| 参数 | 说明 |
|------|------|
| **Number of Simulated Users to Group by** | 集合点用户数 |
| **Timeout (ms)** | 超时时间（0 = 无限等待） |

**典型用途**：模拟并发峰值，创建集合点。

---

## BeanShell Timer (已弃用)

使用 BeanShell 脚本计算延迟。

> ⚠️ 建议使用 **JSR223 Timer + Groovy**。

---

## JSR223 Timer

使用 JSR223 脚本计算延迟，推荐 Groovy。

### Groovy 示例

```groovy
// 返回延迟毫秒数
def delay = 1000  // 1 秒
if (vars.get("iteration") == "1") {
    delay = 5000  // 首次迭代 5 秒
}
return delay
```

| 参数 | 说明 |
|------|------|
| **Language** | 脚本语言 |
| **Script** | 计算延迟的脚本 |
| **Cache compiled script** | 缓存编译脚本 |

---

## 定时器使用技巧

### 选择合适的定时器

| 场景 | 推荐定时器 |
|------|-----------|
| 模拟真实用户思考时间 | Uniform Random Timer |
| 需要固定延迟 | Constant Timer |
| 控制请求速率 | Constant Throughput Timer / Precise Throughput Timer |
| 模拟并发峰值 | Synchronizing Timer |

### 作用域注意事项

- 定时器放在 Thread Group 级别 → 影响所有采样器
- 定时器放在 Controller 级别 → 仅影响该 Controller 下的采样器
- 定时器放在 Sampler 级别 → 仅影响该采样器
- 多个定时器的时间会**累加**
